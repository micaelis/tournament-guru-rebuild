# Tournament Guru

Youth-sports tournament discovery and reviews. Coaches, parents, and team managers find events by age / gender / competition level / geography, read verified reviews from people who actually attended, and message the host directly. Event directors claim their listing, upgrade to a paid feature slot, and reply.

Built on Next.js 16 (App Router, React 19, Server Actions) + Supabase (Postgres 15, RLS, Storage, Auth).

## Quick start

```bash
# 1. Install dependencies (requires Node 20.9+).
npm install

# 2. Point at a Supabase project.
cp .env.staging.example .env.local
# edit .env.local with your project's URL and anon key

# 3. Run the app.
npm run dev

# 4. Verify (before commits, and in CI):
npm run typecheck        # tsc --noEmit
npm run lint             # next lint
```

Open http://localhost:3000. The header should render "Sign in" (logged out) or your initial + Log out (logged in).

## Required env vars

Two, both public (safe to expose to the browser — they're the Supabase anon key + URL):

```
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-jwt>
NEXT_PUBLIC_SITE_URL=http://localhost:3000     # for email confirmation redirects
```

Never commit `.env.local`. Never store secrets in `.claude/settings.json` or any other tracked file (see [CLAUDE.md](CLAUDE.md) · "Secrets").

## Key data-model conventions

- Auth is Supabase (`auth.users`); the app profile lives in `public.profiles`. A trigger creates a matching profile row on signup.
- Every table stores user data with **RLS on**. Public reads are exposed via SECURITY DEFINER views (`review_author_badges`, `event_host_logos`) so the `profiles` base table stays fully locked. Public marketing surfaces read through SECURITY DEFINER RPCs (`get_event_directors`, `get_director_profile`, `get_platform_stats`).
- The single event search RPC is `search_events_page` (trigram + tsvector). If it's not deployed, `lib/supabase/queries.ts::searchEventsPage` falls back to a PostgREST path — it can't filter on age/gender/level/surface joins and returns no coordinates. The API response carries a `source` field so callers can distinguish.
- The `events → event_profiles` link is the "recurring parent tournament". When a future event has no reviews of its own we fall back to sibling reviews (past editions) via `event_profile_id`.
- Reviews carry a denormalized author display (username, user_role). The Coach vs Attendee split is `user_role ilike '%coach%'`, mirrored by `recalc_event_ratings()` and `get_event_review_counts()`.

## Migrations

- Timestamped filenames `YYYYMMDDHHMMSS_slug.sql`. Existing ones start `20240101…`; new ones start with today's YYYYMMDD.
- **Never** edit a historical migration. Add a new one that supersedes.
- Two files are demo-only (`20240101000010_refresh_event_dates_for_demo`, `20240101000015_seed_bubble_recent_reviews`) and are **destructive on populated databases**. They are excluded from `schema.sql` and carry DO-NOT-RE-RUN banners.
- `supabase/proposals/` holds drafts that need operator sign-off before they're promoted to numbered migrations. Currently:
  - `h2_rls_on_remaining_tables.sql` — RLS + policies for event child tables, sponsors, event_profiles, etc.
  - `h3_storage_bucket_policies.sql` — Storage bucket inventory + RLS.

## Rate-limiting

Two layers:

- **App layer (`lib/rate-limit.ts`)**: per-IP fixed-window counter, in-process per-instance. Gates `/api/search-log` (30 / 5 min), `/api/events/search` (60 / min), `submitEventHostContact` and `submitContactRequest` (5 / 10 min).
- **DB layer (`20260714100007_h5_rate_limits.sql`)**: global per-minute burst cap via a SECURITY DEFINER touch function + `before insert` triggers on `search_queries` (1000 / min) and `contact_requests` (60 / min).

For distributed attackers, add Upstash / Vercel KV and swap the in-process bucket for a persistent one.
